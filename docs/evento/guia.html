Um aplicativo onde o operador da fábrica registra o problema que vê no dia a dia, o gestor avalia e transforma a boa ideia em projeto, e a liderança acompanha quanto isso devolveu em dinheiro e produtividade. No semestre passado era só uma tela com dados fictícios; agora tem um servidor próprio, login por perfil e banco de dados — é um sistema de verdade.

Como foi construído

App Android

Kotlin com Jetpack Compose e Material 3, no padrão MVVM. Conversa com o servidor pela biblioteca Retrofit. Os gráficos foram desenhados à mão em Canvas, sem biblioteca externa.

Servidor (API)

Java 21 com Spring Boot. Organizado em camadas: controller recebe, service decide, repository acessa o banco. Segurança com Spring Security e token JWT.

Banco e ambiente

MongoDB, banco de documentos. Tudo sobe com Docker: dois containers, um comando, sem instalar Java nem banco na máquina.

Perguntas que vão fazer — e a resposta pronta

Por que vocês escolheram MongoDB e não um banco tradicional?

O desafio exigia banco NoSQL. Encaixou bem: uma ideia e um projeto têm listas dentro deles — indicadores, histórico de alterações, atualizações de progresso — e no Mongo isso fica tudo em um documento só, sem precisar de várias tabelas amarradas.

Como funciona o login e por que ele é seguro?

A senha nunca é guardada como texto: o servidor grava um resumo embaralhado dela (BCrypt), de onde não dá para voltar à senha original. Ao entrar, o servidor devolve um token que vale 8 horas e carrega dentro dele qual é o perfil da pessoa. Toda chamada seguinte leva esse token, e o servidor confere se aquele perfil pode fazer aquela operação.

E se alguém tentar acessar algo que não pode?

Recebe erro 403 e uma mensagem explicando. Isso vale até se a pessoa chamar o servidor por fora do app: a regra está no servidor, não na tela. Dá para demonstrar ao vivo — com o token de operador, a rota de projetos responde 403.

Como vocês garantem que funciona? Testaram?

São 69 testes automatizados que sobem um banco de verdade em container e exercitam as regras: quem pode o quê, se o operador só vê as próprias ideias, se a ideia respeita o fluxo de etapas e se as contas do painel batem. Toda vez que alguém envia código, o GitHub roda esses testes e compila o aplicativo sozinho.

Os números do painel são reais ou chutados?

São calculados na hora, a partir dos projetos cadastrados. O ROI é retorno menos investimento, dividido pelo investimento. Nada disso fica salvo no banco, justamente para nunca ficar desatualizado em relação aos valores dos projetos.

Qual foi a parte mais difícil?

Duas coisas. Primeiro, trocar os dados fictícios do protótipo pelas chamadas reais sem quebrar as telas: resolvemos mantendo os mesmos nomes de campos e formatando os valores na entrada do app. Segundo, um erro sutil: ao sair do aplicativo, uma tela ainda recarregava por um instante e, já sem o token, mostrava "sessão expirada" sem motivo. Achamos a causa e corrigimos em duas camadas.

Tem inteligência artificial?

Ainda não. Era um diferencial opcional do desafio e priorizamos entregar o essencial funcionando e testado. A base já está pronta para receber: o próximo passo seria pontuar e priorizar as ideias automaticamente, e gerar análises dos resultados para a liderança.

Dá para usar em produção amanhã?

O sistema funciona de ponta a ponta, mas roda na máquina de quem o executa. Para uso real faltaria publicar o servidor num provedor, colocar HTTPS e trocar as senhas de demonstração. A aplicação já foi feita pensando nisso: tudo que muda de ambiente está em variáveis de configuração.

Quanto tempo levou e como se dividiram?

Uma sprint de duas semanas, partindo do protótipo do semestre anterior. O trabalho foi dividido entre servidor, aplicativo e documentação, com revisão por pull request antes de entrar no projeto — inclusive o ajuste final, que corrigiu o erro do logout e a versão do banco.

E se a internet cair ou o servidor estiver fora?

O aplicativo mostra um aviso explicando e um botão para tentar de novo, em vez de travar ou fechar. Cada erro do servidor vira uma mensagem em português na tela.

Dicionário rápido

API REST

O servidor que guarda os dados e aplica as regras. O aplicativo não decide nada sozinho: ele pergunta para a API.

Token JWT

Um crachá digital assinado, entregue no login. Carrega quem é a pessoa e qual seu perfil, e vale 8 horas.

Docker

Empacota o servidor e o banco com tudo que precisam. Quem for avaliar roda um comando e funciona igual em qualquer máquina.

MongoDB

Banco que guarda documentos em vez de linhas e colunas — parecido com uma ficha completa de cada ideia ou projeto.

Jetpack Compose

Forma moderna de montar telas no Android: a tela é descrita em código e se redesenha sozinha quando o dado muda.

Teste automatizado

Um programa que usa o sistema no nosso lugar e avisa se alguma regra parou de funcionar depois de uma mudança.
